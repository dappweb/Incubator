## 8. 错误处理决策树

```
用户执行操作
    │
    ▼
操作失败
    │
    ├─ 【钱包错误】
    │   ├─ "User denied" → 用户取消签名 → 提示"取消操作"
    │   ├─ "No Ethereum" → 未安装钱包 → 提示"安装 MetaMask"
    │   └─ "Wrong network" → 网络错误 → 提示切换到 Sepolia
    │
    ├─ 【合约错误】
    │   ├─ "bind referrer first" → 未绑定推荐人 → 跳转到推荐人界面
    │   ├─ "already bound" → 已绑定过 → 显示现有推荐人
    │   ├─ "invalid qty" → 数量范围错误 → 提示"数量 1-10"
    │   ├─ "insufficient balance" → 余额不足 → 提示"余额不足"
    │   └─ "invalid referrer" → 推荐人无效 → 提示"推荐人地址无效"
    │
    ├─ 【授权错误】
    │   ├─ "allowance too low" → 授权不足 → 自动重新授权
    │   └─ "approval failed" → 授权失败 → 重试授权
    │
    ├─ 【网络错误】
    │   ├─ "RPC timeout" → 网络延迟 → 重试或稍后再试
    │   ├─ "Transaction failed" → 交易被 revert → 查看错误原因
    │   └─ "Gas limit exceeded" → Gas 不足 → 增加 Gas
    │
    └─ 【未知错误】
        └─ 显示错误原文 + "请检查合约或联系支持"

│
▼
重试或返回│
    ▼
┌──────────────────┐
│ 用户可选择：      │
│ ✓ 重试            │
│ ✓ 返回上一步      │
│ ✓ 联系支持        │
└──────────────────┘
```

## 10. 性能优化建议

### 数据查询优化

```javascript
// ❌ 不好：每个订单分别查询
for (const orderId of userOrderIds) {
  const order = await getMachineOrder(provider, orderId);
}

// ✅ 好：并行查询
const orders = await Promise.all(
  userOrderIds.map(id => getMachineOrder(provider, id))
);
```

### 授权优化

```javascript
// ❌ 每次购买都重新授权到完全覆盖
approve(amount1);
approve(amount2);

// ✅ 首次授权到充足额度，后续直接执行
approve(MAX_INT);  // 一次性最大授权
// 后续购买无需再授权
```

### 事件监听优化

```javascript
// ❌ 轮询查询
setInterval(() => {
  getTeamStats();
}, 5000);

// ✅ 事件驱动
contract.on("MachinePurchased", (user, orderId, qty, amount, referrer) => {
  updateTeamStats(referrer);
});
```
